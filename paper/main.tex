\begin{abstract}
% DRAFT. Every number below is traceable to experiments/RESULTS.md; see the claim ledger.
Object-centric world models are routinely credited with predicting \emph{which} objects in a
scene will change. We show that the benchmarks used to support that claim are degenerate, and
that the degeneracy is not fixable by filtering the data.
We audit three successive change-detection benchmarks on a tabletop manipulation task, each
constructed to remove its predecessor's shortcut, using a battery of eleven rules that have no
learned parameters or one.
A motion-filtered benchmark is won by \emph{velocity} (predict change iff the object is
already moving, F1 $0.927$); the onset-filtered benchmark that removes the velocity shortcut is
won by \emph{geometry} (predict change for the single object nearest the actuator---zero
parameters, F1 $0.961$); and an interaction-filtered benchmark that removes the geometry
shortcut is won by \emph{propagated kinematics} (F1 $0.955$).
The best trivial rule never falls below $0.93$.
Five published object-centric world models---GNS/DPI-Net, C-SWM, SlotFormer, PETS and
NPS---implemented from their papers, trained with their native objectives and capacity-matched,
lose to these rules on every benchmark, and are degenerate in a second sense: every one flags
essentially all objects as changing (recall $0.9986$--$1.0000$).
We give the mechanism---with a single actuator and local contact the label is recoverable from
one scalar, and a filter only chooses which---and release the audit battery, together with the
methodological requirement that it be run with rules invented \emph{against} the benchmark
under test rather than against the one it replaces.
\end{abstract}

\section{Interactive demo}

The paper's central claim is checkable in a browser.
\url{https://paramthakkar123.github.io/WorldModelsWorkshop/} runs the actual
trained gate and delta head (5,636 parameters) live against planar physics and
recorded MuJoCo/Box2D/Chipmunk episodes, scored against the eleven trivial rules
frame by frame. Four tasks: a sandbox the reader drives, replay across four
engines, count transfer with one checkpoint, and CEM planning through the model.
No server, no build step; the JavaScript forward pass is checked against PyTorch
to $10^{-4}$ by \texttt{tests/test\_web\_export.py} and served from \texttt{docs/}
via GitHub Pages.

\section*{Reproducibility statement}
Every number traces to \texttt{experiments/RESULTS.md} and a directory in
\texttt{experiments/runs/} with \texttt{config.json}, \texttt{metrics.csv}, and
\texttt{summary.json}. The audit battery \texttt{experiments/onset\_shortcut\_audit.py}
and \texttt{experiments/audit\_battery.py} run on any benchmark via
\texttt{python -m experiments.audit\_battery --test yours\_test.npz --val yours\_val.npz}.
Data generation is seeded and deterministic; splits are episode-disjoint via
\texttt{experiments/build\_clean\_splits.py}, which replaces the leaky splits noted in
\texttt{RESULTS.md}. The test suite (\texttt{pytest tests/}, 202 tests) pins metrics,
splits, and the browser export. Checkpoints in \texttt{models/checkpoints/} are the
exact weights evaluated and exported to \texttt{docs/assets/model.json}.
