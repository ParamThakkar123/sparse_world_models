What you are looking at

The model is real

The gate and delta head are exported straight from the paper's checkpoints — … parameters — and the JavaScript forward pass is checked against PyTorch to 1e-4 by tests/test_web_export.py. Two checkpoints ship: the live sandbox runs the planar-trained gate because the sandbox is planar physics, and the replay tab runs the tabletop-trained one. Scoring a tabletop model on live planar physics would put a domain shift on screen with nothing to label it.

The rules have no parameters

nearest_to_pusher predicts change for the single object closest to the pusher. Nothing is fitted. On the paper's onset benchmark it scores F1 0.925 against the learned gate's 0.694. The thresholded rules have exactly one parameter, and the slider lets you check that no particular setting is doing the work.

Why it happens

With one point-like pusher and objects kept apart, contact is spatially unambiguous: the pusher is near at most one object and that object is the one that moves. The label is recoverable from a single scalar. Three successive benchmarks each removed one such scalar and were promptly won by the next.

What still stands

The gate's real advantage is not detection but error suppression: objects it leaves off are copied forward exactly, so they accumulate no error, and the gap over a dense monolith grows with object count. Turn the object count up on the Count transfer task and watch the untouched objects stay put.

Full results, including the three claims of ours that proper baselines refuted, are in experiments/RESULTS.md. The audit battery runs on any benchmark: python -m experiments.audit_battery --test yours_test.npz --val yours_val.npz.
